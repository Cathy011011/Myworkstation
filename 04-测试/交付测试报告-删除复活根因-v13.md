# 交付测试报告 · 删除后复活根因修复（v13）

- 日期：2026-09-08 14:05
- 地址：https://workbuddy.link/p/8ZxrlsT0cik2jMIZ8SOM2o （v13 已发布，顶栏角标 `v13`）
- 缺陷：**日程（及所有模块）删除任务后点「刷新云端数据」，记录复活**

## 根因（已实证，非推测）

v11 墓碑裁决代码：

```js
if(!rec || (rec.properties && rec.properties['已删除']===true)){ delete t[tid]; }
```

**"云端按 id 查不到"被当成"云端已删除"**。而云端在删除后会出现**短暂查不到该记录**的窗口（写入未即时生效/查询滞后），墓碑因此被提前解除；等记录再次出现在查询结果里，就**复活**了。

## 修复（v13）

1. 墓碑**只在云端明确返回 `已删除=true` 时解除**；查不到 → 保留墓碑继续隐藏（仅 7 天未确认才清理）
2. 新增**内容指纹** `fpOf()`：本地 id 与云端 record_id 错位时，按内容认出云端真身，并对真身补发删除
3. 墓碑补删优先使用认出的云端真身 id

## 测试结论

### 1. 复活场景对照（同一用例，唯一变量=代码版本）

模拟：登录态正常（删除接口返回成功）+ 删除后云端查询短暂缺失再恢复，跨越 11 次查询、连续点 3 次「刷新云端数据」。

| 版本 | 删除后可见 | 结论 |
|---|---|---|
| v11 | ✅ 可见（复活） | 复现用户缺陷 |
| **v13** | ❌ 不可见 | **修复生效** |

### 2. mock 全场景回归（7/7 PASS）

| 场景 | 结果 |
|---|---|
| 云端活记录 + 写入 401 | 删除→刷新→不复活 ✅ |
| 删除假成功 | 墓碑保留、不复活、自动重试 ✅ |
| 云端已软删 | 墓碑自动解除 ✅ |
| LLM 主模型失效 | 自动降级成功 ✅ |

### 3. 线上真实端到端（7/7 PASS）

服务端真实造数 → 线上页面删除 → **连续点 3 次「刷新云端数据」** → 整页刷新 → 服务端清理。结果：记录始终不可见，云端无残留。

## 验收步骤

1. 打开链接，**Ctrl+F5 强制刷新**（手机清浏览器缓存或用无痕窗口）
2. 确认右上角角标显示 **v13**（不是 v13 = 仍是缓存）
3. 日程模块删除任意任务 → 点「刷新云端数据」→ 不再复活
4. 若徽章提示"登录已过期"：刷新页面重新登录后，之前删除的会自动补同步到所有设备
