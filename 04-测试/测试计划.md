# 测试计划

> 对象：生活工作台 V2（七视图 + 六张在线数据表）
> 用例全集见 `04-测试/测试用例.md`，缺陷登记见 `04-测试/缺陷清单.md`，结论归档见 `04-测试/测试报告.md`

## 一、测试目标

验证三件事：
1. **功能完整**：七个视图的增删改查、筛选、切换都符合需求定义
2. **数据真的在线**：换设备换浏览器是同一份数据，不是浏览器本地的假象
3. **不会静默失败**：网络异常时看得见、说得清、点得动重试

## 二、测试范围

| 范围 | 内容 |
|---|---|
| 在范围内 | 七视图 UI、六张表的读写、跨端同步、容错降级、响应式、交付合规（外链/体积） |
| 在范围内（条件验证） | 翻译与问答的真实调用 —— 取决于沙盒是否放行跨域，先看探针结论 |
| 不在范围内 | 母版原页面（只读参考，不测）、平台自身稳定性、付费/权限体系 |

## 三、测试环境

| 项 | 说明 |
|---|---|
| 被测对象 | 资料库协作态在线页面 `/space/d/{nodeId}` |
| 桌面 | Chrome 最新稳定版，窗口 ≥1280px |
| 移动 | iPhone Safari（含刘海机安全区）、Android Chrome；窄窗口模拟 ≥375px |
| 跨端验证 | 两个不同浏览器 + 一台手机，同时打开同一链接比对 |
| 网络异常模拟 | 浏览器 DevTools 切 Offline / Slow 3G；以及对数据表接口打断点强制失败 |

## 四、测试阶段与准入

```
阶段一 原型评审    → 本地 Demo 交互与视觉对齐，已在进行
阶段二 探针验证    → 沙盒跨域连通性，决定 AI 方案      【准入门槛，不通过不进下一阶段】
阶段三 建表连通    → 六表建成、SDK 读通、字段与字典一致
阶段四 功能测试    → TC-07 ~ TC-46，七个视图的业务行为
阶段五 同步测试    → TC-47 ~ TC-50，跨设备一致性
阶段六 容错测试    → TC-51 ~ TC-56，失败可见可重试
阶段七 兼容测试    → TC-57 ~ TC-60，桌面与移动
阶段八 合规测试    → TC-61 ~ TC-64，密码不外露、无外链、体积达标
阶段九 回归        → 缺陷修复后重跑受影响用例
```

**准入规则**：阶段二探针不通过时，AI 相关需求（REQ-05/REQ-06）切换到降级方案后继续，不得卡住整体进度。

## 五、通过标准

| 级别 | 标准 |
|---|---|
| 阻断 | **0 个**。任何数据丢失、白屏、写入静默失败、密钥泄露都算阻断 |
| 严重 | **0 个**。某个视图打不开、某张表读写不通、移动端元素溢出导致不可点 |
| 一般 | ≤ 3 个，且需有明确修复时点 |
| 提示 | 不限，记录即可 |

额外硬门槛：
- 首屏渲染完成 ≤ 3 秒（3G 网络放宽到 6 秒）
- 任何一次增删改，5 秒内必须在线上表中体现
- 页面内第三方域名图片外链数 = 0

## 六、缺陷管理

```
发现 → 登记到《缺陷清单》→ 定级 → 修复 → 回归勾选 → 关闭
```

字段：缺陷ID、发现阶段、关联用例、现象、复现步骤、实际结果、期望结果、级别、处理人、状态、回归日期。
级别定义同上「通过标准」。

## 八、主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 沙盒不放行跨域请求 | 翻译/问答无法页面内实时 | 降级为「数据表队列 + 对话侧回写」，字段已预留，不用改表 |
| date 字段时区差一天 | 日程/规划按天筛选错乱 | 已用「text 日期键 + date 展示」双写规避，TC-08 专项验证 |
| 数据超 50 条不翻页 | 只能看到前 50 条 | 统一封装 `queryAll`，TC-50 灌 60 条数据验证 |
| 字段名与 getSchema 不一致 | 查询直接失败 | 启动时断言比对，TC-49 专项验证 |
